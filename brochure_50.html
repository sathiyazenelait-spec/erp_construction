System Architecture

Backend REST APIs, Frontend Routing, and AI Pipelines

BuildCon ERP employs a highly scalable, decoupled client-server architecture model. The client-side dashboard framework runs on Next.js 14, connecting to a multi-threaded Spring Boot 3 enterprise application and a dedicated FastAPI service for running generative AI models.

Technical Stack Details

Layer Technology Responsibility
Frontend Client Next.js 14, React, TS, Tailwind CSS Role Dashboards, Real-time Charts, Responsive Layouts
Java Backend Spring Boot 3, Java 17, Hibernate JPA Business Logic, Multi-tenant Data APIs, Security Filter Chains
Python AI Backend FastAPI, Uvicorn (Port 8001) Project Performance Audits, Cost Variances, Cash Flow AI
Database MySQL 8.x Transactional Ledgers, User Accounts, Tenant Registry

Security Filter Chain & Decoupling

All network interactions use JSON-encoded requests. Spring Security handles endpoint protection, verifying signature validation keys encoded in client-header HTTP bearer authentication tokens on every dispatch.

The backend employs database connection pools (HikariCP) to interact with relational schemas, ensuring fast transactional speeds during heavy construction logs updates.

Subscription Tier System

Modular Control and Pricing Tiers

To provide flexible SaaS packages, BuildCon ERP employs a subscription mapping engine. The features, dashboards, and role dropdowns rendered on login screens are toggled dynamically based on the active client subscription tier.

Tiers Mapping

Growth

Designed for field execution. Unlocks Project Manager, Construction Manager, Senior Site Engineer, and Subcontractor portals. Limits business and financial controls.

Premium

Adds back-office control. Unlocks Finance & Accounts ledgers, Quantity Surveyor BOQ audits, Procurement RFQ matching, and HR managers.

Enterprise

Full platform access. Enables the Chairman Portal, Managing Director cockpit, all Director roles, Sales CRMs, and Digital Marketing campaigns.

Database Configuration & Verification

The organizations table stores subscription levels under the subscription_tier column. When an employee logs in, the authentication handler queries GET /api/organizations to fetch their tenant context, parsing the subscription tier to lock or open pages.

Access Security

Landing Page OTP Verification Gate

Access control starts at the landing page. Before hitting the authentication pages, the portal selection panel remains locked behind an OTP verification modal. This acts as a primary firewall gate for organization tenants.

OTP Lifecycle

  • The user selects their corresponding organization dropdown on the landing page, calling GET /api/organizations.
  • Clicking "Send OTP" calls the backend to generate a deterministic 4-digit code using a time-sensitive algorithm.
  • The modal displays a 30-second countdown timer. For security, the verification route accepts the current window code plus two previous windows to prevent minor clock drifts.
  • On verification, organization configurations (Org ID, Tier, Domain) are committed to client localStorage, unlocking role portals.

Login Gateways

Once unlocked, users are directed to role-specific login interfaces: `/login/chairman`, `/login/director`, or `/login/manager`. All forms submit username and password details, returning JWT bearer tokens which authorize subsequent API fetches.

Warning: Organization sessions expire after 24 hours. Local storage configurations are cleared on logout transactions.

Chairman Portal: Executive Summary Data Origin

Dynamic DB Queries vs Frontend Static Datasets

Enterprise Tier Only

Here is the technical data mapping for the Executive Summary Dashboard cards and trends:

Dynamic Database-Driven Metrics

  • Total Projects (11 Projects): Mapped to the projects table, counted dynamically by organization ID in getDashboardStatsUnified. Statuses are parsed as 5 Active, 0 Delayed, 6 Planning. These projects are created by the Chairman and Project Directors in the enterprise organization.
  • Total Budget Value (₹ 52.00 Cr): Sum of all project budgets updated directly by the Project Director or Managing Director in the database (calls project.getBudget()).
  • Claims Expense MTD (₹ 0.00 Cr): Calculated dynamically in the backend by querying the progress_claims table, summing up the amount_requested values where status is APPROVED or PAID.
  • Active Staff (27): Calculated using a simulated formula in the Java backend: 12 + (pmCount * 3) where pmCount is the number of project managers in the organization.

Static Frontend Datasets

  • Equipment Status (94%): Static display value shown directly in the client component code, which logs "2 cranes under service" as details.
  • Revenue & Profit Trends (Last 6 Months): Static chart arrays (Jan–Jun) stored directly in the frontend component.
  • Projects by Status: Hardcoded to show 18 Total Projects (12 On Track, 4 Delayed, and 2 Critical) in the client-side donut chart.
